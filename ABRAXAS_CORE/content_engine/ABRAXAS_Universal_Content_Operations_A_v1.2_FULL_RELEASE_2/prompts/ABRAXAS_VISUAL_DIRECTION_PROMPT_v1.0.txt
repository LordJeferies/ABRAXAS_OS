ABRAXAS · PROMPT MAESTRO DE DIRECCIÓN VISUAL v1.0

ROL
Actúa como Lead Product Designer + macOS Interaction Designer + Creative Technologist encargado de evolucionar ABRAXAS sin degradar su sistema funcional. Tu trabajo no es “hacerlo Apple-like” mediante blur y botones redondos: debes usar la anatomía, jerarquía, control de densidad, progressive disclosure, motion y calidad perceptual propias de una aplicación premium diseñada para macOS, combinadas con storytelling de producto de las páginas actuales de Apple.

OBJETIVO VISUAL
La interfaz debe sentirse tecnológica, precisa, calmada y premium. ABRAXAS mezcla una sensibilidad retro/fundacional —geometría, compás, proporciones, monograma— con tecnología contemporánea —procedural graphics, data, glass funcional, inspectors, animación contextual—. Negro/graphite es el entorno; bone-white y oro/bronce son acentos de identidad. Los colores de cliente solo entran cuando el contexto del cliente lo justifica.

APPLE FIRST
1. Content is king: en story mode una idea fuerte por escena y grandes áreas de respiración.
2. Liquid Glass solo en functional layer: topbars, sidebars, popovers, utility windows, segmented controls, overlays y controles flotantes. No aplicar glass indiscriminadamente a cards o grandes bloques de contenido.
3. Navigation: mínima, contextual, adaptativa. Story mode puede esconder sidebar; workspace mode usa sidebar/toolbar/inspector cuando ayudan.
4. Controls: desktop-sized, coherentes, estados hover/pressed/focus, no pills innecesarios.
5. Motion: source-anchored, morph/materialize, opacity + small translation; nada ornamental sin función. Prefers-reduced-motion obligatorio.
6. Geometry: radios concéntricos y spacing sistemático.

HOME / BRAIN NAVIGATOR 2.0
El cerebro procedural es la imagen primaria del Home Visual. Debe percibirse inequívocamente como cerebro y tener mucha presencia. Está formado por cientos/miles de pequeños chevrons o triángulos abiertos basados en la A de ABRAXAS, no puntos genéricos. Paleta: bone #f4ead6, gold #d8b46c, bronze #b78338/#8a6532, white #ffffff, con opacidades variables.

Escala: 100% reproduce exactamente el baseline de v0.9.6.1 y es el tamaño mínimo. El usuario puede ampliar progresivamente hasta 200%. Zoom se realiza alrededor del centro cerebral, no simplemente ampliando el canvas entero. Partículas y hotspots deben conservar correspondencia espacial.

Hotspots: He, Shim, Production, Calendar, Assets, Brand Intelligence. Cada hotspot debe parecer parte del cerebro: un control visible con símbolo monocromático, una leader line fina que conecta el control con el tejido cerebral y un popover al hover/focus con: nombre, “Qué hace”, descripción breve y CTA “Abrir herramienta”. Nunca esconder totalmente los controles hasta hover.

Overlay: cualquier copy, status o zoom control sobre el cerebro debe usar Liquid Glass translúcido aproximadamente rgba(18,18,20,.42), backdrop blur/saturate y borde blanco muy tenue. El cerebro debe seguir visible detrás. Evitar cajas opacas.

MORPH POR SCROLL
En Home Visual, el mismo campo procedural puede reinterpretarse según capítulo: brain → routes → queue → calendar → network. La transición es interpolación continua de posiciones, no un reemplazo abrupto de imágenes. Al regresar a Overview debe recuperar brain. El morph no existe en Solo texto.

PRODUCT STORY
Dashboard se llama Home. Home, Clients, Brand Intelligence y Roadmap usan escenas narrativas, highlight rails con scroll-snap, pequeños selectores, disclosures y media/data modules. No convertir storytelling en “texto gigante sobre negro”. Titulares tienen escala contenida y cada viewport debe incluir suficiente contexto visual para entender de qué trata la información.

WORKSPACES
He y Shim: wizard con una decisión principal por paso. Production: task manager calm-first. Assets: media browser + mapping. Content Studio: editor 1×1; en visual usar unit list / preview / inspector cuando convenga. Calendar: calendario real. AI Results: import/hydration. Cada herramienta puede tener UX interna propia; no repetir el mismo card-grid.

EL ARQUITECTO
Utility window flotante fixed right, independiente del layout. Launcher usa el icono compás/mano aprobado con forma de app icon. Preguntas rápidas actualizan solo el panel, nunca renderShell completo. Contexto: módulo + story section + content_id + progreso + tareas cuando existan.

DALA / OHZI / CLEANMYMAC / REFERO
Dala se usa solo para inspiración del particle field. OHZI solo para sensación de objeto inmersivo en un void. CleanMyMac para módulos protagonistas y acción principal. Refero/Awwwards para ritmo/sliders/overlays. Si una referencia contradice Apple HIG, Apple gana.

NO HACER
No SaaS dashboard genérico. No mosaicos de cards como estructura universal. No glass-on-glass. No texto de 100+ px como solución por defecto. No iconos emoji/engranajes simples. No colores saturados sin semántica. No animación ornamental. No ocultar navegación esencial. No romper offline.

ACCEPTANCE
La pantalla debe sentirse ordenada antes de leerse. El usuario debe reconocer dónde está, qué puede hacer y qué viene después. Home debe comunicar el sistema mediante el cerebro sin bloquearlo con overlays. Workspaces deben sentirse más sencillos que el proceso que controlan. La interfaz debe conservar identidad ABRAXAS aunque tome reglas de Apple.
