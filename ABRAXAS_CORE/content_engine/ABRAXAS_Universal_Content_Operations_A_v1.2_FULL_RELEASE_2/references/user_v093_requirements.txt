Sí: el cliente seleccionado cambiará el accent system de toda la plataforma, sin convertir cada cliente en una aplicación visualmente distinta.

Eso encaja directamente con HIG. Apple recomienda que una marca pueda expresarse mediante un accent color, pero que la marca permanezca subordinada al contenido y conserve patrones familiares. También señala que el color personalizado puede ser especialmente efectivo como accent en interfaces predominantemente monocromáticas.

Lo más importante que extraigo del HIG completo

Hay varias reglas que ahora incorporaría formalmente a ABRAXAS Interface System 1.0.

Purpose / Familiarity / Feedback / Responsibility. Apple vuelve a poner estas ideas entre sus principios fundamentales: la intención debe ser evidente, los patrones deben resultar familiares, cada acción necesita feedback claro y el sistema debe ser transparente sobre qué hace. En ABRAXAS esto significa que cualquier pantalla debe responder Dónde estoy / Qué puedo hacer / Qué ocurrió / Qué sigue.
Progressive disclosure como regla sistémica. Los Disclosure Controls de Apple recomiendan mantener visible lo más importante y esconder los detalles avanzados hasta que sean relevantes. Esto pasa a gobernar prompts profundos, VFX avanzados, Branding prompts, Production Tasks, configuraciones de He y propiedades visuales.
Sidebar para destinos; inspector para propiedades. Sidebars están concebidas para moverse entre áreas o colecciones principales, mientras que paneles/inspectors sirven para información complementaria del elemento seleccionado. ABRAXAS dejará de utilizar la sidebar para intentar mostrar estado interno de una pieza.
Split views donde realmente tienen sentido. Apple permite presentar panes adyacentes de navegación/contenido/inspector y ocultar columnas secundarias al reducir el ancho. Esto encaja perfectamente con el editor visual avanzado:
Units → Preview → Inspector.
Lists antes que grids cuando importa leer. Lists/Tables son particularmente útiles cuando hay información jerárquica o textual extensa. Production Queue, Resultados IA y Assets usarán más list/detail y menos card-grid masivo.
Popovers para decisiones breves. Un popover debe contener poca información o unas pocas acciones relacionadas y desaparecer al terminar. Eso lo aplicaremos a Leyenda, Mover fecha, Cambiar estado, información breve de formato y pequeñas configuraciones.
Sheets para tareas acotadas. No se van a abrir páginas completas para operaciones pequeñas como vincular un asset o mapear un resultado.
Menus para comandos secundarios. Apple considera los menus una manera eficiente de revelar comandos sin ocupar espacio permanente. De ahí saldrán Duplicar / Mover / Archivar / JSON / Historial técnico, mientras la acción principal permanece visible.
Toolbar limitada a acciones frecuentes. En macOS la toolbar pertenece al frame superior de la ventana, y HIG recomienda mantener comportamiento y apariencia coherentes. Esto reducirá drásticamente los topbars de ABRAXAS.
Search mucho más importante. Apple muestra el search field no solo para buscar texto, sino para filtrar estructuras profundas y utilizar scopes/tokens. La Biblioteca debería evolucionar hacia algo como:
Moka · Carrusel · Review · Agosto
mediante tokens/chips buscables.
Drag & Drop debe comunicar source y destination. Esto es particularmente relevante para Calendar y Assets. Apple define explícitamente source/destination y diferencia move de copy. ABRAXAS deberá dar feedback visual claro cuando una pieza se está calendarizando, moviendo o vinculando.
File Management debe sentirse familiar. En Mac las personas ya poseen modelos mentales basados en Finder y comandos New/Open. El Workspace de Assets aprovechará esa familiaridad: ruta visible, carpeta destino, reveal/import/sync y archivos huérfanos claramente identificados.
Undo/Redo. Apple destaca que poder revertir acciones da libertad para explorar sin miedo. Esto es muy importante para ABRAXAS: mover un contenido, cambiar status, modificar estructura o reemplazar un asset debe poder revertirse. Lo incorporaría primero como undo stack local.
Feedback proporcional. HIG distingue status pasivo de warnings y errores de mayor importancia. Guardado automático, por ejemplo, no necesita una alerta; puede mostrar un pequeño Guardado. Un resultado que sobreescribiría contenido aprobado sí necesita confirmación explícita.
Help contextual. Apple recomienda que las instrucciones relacionadas con una parte de la interfaz aparezcan cerca de esa parte y advierte que si hacen falta párrafos enormes para explicar un control, probablemente hay que simplificar el control. Esto es exactamente lo que necesitaba Cómo usar ABRAXAS.
Dark Mode no es invertir blanco por negro. Apple utiliza fondos más apagados, foregrounds más luminosos y jerarquías elevadas para popovers/sheets. También recomienda contrastes mínimos y colores adaptativos. Esto cambia varios negros absolutos actuales de ABRAXAS por superficies semánticas.
Typography necesita menos variantes, no más. Apple advierte que demasiadas fuentes dificultan jerarquía y legibilidad. En el HTML usaremos principalmente system-ui con peso, tamaño y tracking para crear jerarquía, no cinco familias tipográficas.
Mac es un entorno de productividad profunda. HIG destaca el espacio, flexibilidad y capacidad de personalización de macOS, incluido configurar toolbars, ventanas y contenido visible. Esto refuerza que ABRAXAS debe sentirse más cercano a una workstation editorial que a una landing/dashboard SaaS.

Visual Regression Gate ampliado

Además de overflow, solapamientos y responsive, v0.9.3 tendrá un HIG audit propio:

HIERARCHY
¿El contenido gana visualmente a los controles?

HARMONY
¿Los radios, spacing y materiales son coherentes?

CONSISTENCY
¿El mismo control se comporta igual en todos los módulos?

PURPOSE
¿Se entiende inmediatamente para qué sirve la pantalla?

FEEDBACK
¿Toda acción importante confirma qué ocurrió?

DISCLOSURE
¿Se está enseñando información avanzada antes de necesitarla?

COLOR
¿El accent identifica cliente sin confundirse con estado?

ACCESSIBILITY
¿Existe icono/texto además de color?
¿Contraste suficiente?
¿Focus visible?

NAVIGATION
¿Sé dónde estoy y cómo volver?

RECOVERY
¿Puedo deshacer acciones relevantes?

HELP
¿La explicación está cerca del punto de uso?

Ese gate me parece bastante más importante que simplemente intentar “copiar macOS”.

Con esta última revisión, la identidad visual de v0.9.3 queda definida como:

ABRAXAS Interface System 1.0 · Mac Spatial Dark + Dynamic Client Accent

La interfaz estructural es siempre ABRAXAS; la marca activa colorea el sistema sin apoderarse de él.

Y, sobre todo, voy a usar el HIG como un sistema completo de reglas para ABRAXAS, no únicamente como inspiración visual de Liquid Glass. Eso incluye navegación, layout, componentes, feedback, ayuda, búsqueda, archivos, accesibilidad, estados, inputs y recuperación de errores.
