================================================================================
0. RESUMEN EJECUTIVO
================================================================================

ABRAXAS es un Content Operating System.

No debe definirse simplemente como una plataforma para generar contenido, un generador de prompts, un calendario editorial, un gestor de proyectos o una biblioteca de archivos.

ABRAXAS busca convertir conocimiento estratégico, editorial, creativo, visual y operativo —que normalmente vive en la cabeza de un estratega, un director creativo, un fundador o una agencia— en infraestructura reproducible.

La tesis fundamental del producto es:

    ABRAXAS convierte criterio en infraestructura.

El sistema captura:
- cómo es una marca;
- qué defiende;
- cómo habla;
- cómo vende;
- quién es su audiencia;
- qué territorios editoriales puede ocupar;
- qué formatos utiliza;
- cómo debe funcionar cada formato;
- qué estructura narrativa requiere;
- qué no debe hacer;
- qué criterios visuales debe respetar;
- qué copies son correctos;
- qué claims son seguros;
- qué fuentes pueden utilizarse;
- qué debe entregar una IA;
- qué se debe revisar;
- qué tareas faltan para terminar una pieza;
- quién debe ejecutar cada tarea;
- cuándo debe publicarse;
- en qué campaña participa;
- qué pasó con ese contenido hasta llegar a publicado.

A partir de ese conocimiento, ABRAXAS puede transformar una necesidad como:

    "Quiero cinco carruseles de JOC para las próximas dos semanas"

en un sistema de producción que entiende:

    qué pilar cubrir;
    qué formatos de JOC son válidos;
    qué estructura corresponde a cada formato;
    qué territorios no deben repetirse;
    qué prompt debe compilarse;
    qué debe devolver la IA;
    cómo vuelve ese resultado a la pieza original;
    qué imágenes faltan;
    qué copies faltan;
    si necesita grabación;
    quién debe actuar;
    cuándo sale;
    si pasó QA;
    y si ya fue publicado.

La IA es un motor intercambiable dentro de ABRAXAS.

El producto no depende de que una IA concreta sea "la inteligencia" del sistema.

La inteligencia principal de ABRAXAS es:
- estructura;
- criterio;
- contexto;
- memoria editorial;
- reglas;
- flujos;
- QA;
- trazabilidad;
- relaciones entre objetos;
- sistemas de prompts;
- conocimiento de marca.

Una IA puede cambiar.
Un modelo puede quedar obsoleto.
Una herramienta de imagen puede ser reemplazada.
El conocimiento operativo no debe perderse.

================================================================================
1. LA DEFINICIÓN MÁS PRECISA DE ABRAXAS
================================================================================

ABRAXAS es un sistema operativo editorial para creadores, marcas y agencias que captura el conocimiento estratégico y creativo de una marca, lo transforma en estructuras y prompts reproducibles y coordina cada contenido desde la idea hasta su publicación.

Su ventaja no consiste simplemente en producir más contenido automáticamente.

Su ventaja consiste en hacer que:

    calidad
    + identidad
    + estructura
    + criterio
    + proceso

puedan repetirse a escala sin depender permanentemente de la memoria o capacidad individual de una sola persona.

ABRAXAS integra conceptualmente:

    Brand Intelligence
    Branding Method
    Pillars
    Format Library
    Campaigns
    He - Content Factory
    Shim
    AI Handoffs
    Content Studio
    Production Graph
    Production Queue
    Role-based Desks
    Assets
    QA
    Calendar
    History
    Analytics
    El Arquitecto

Todo alrededor de una misma identidad persistente:

    CONTENT.

================================================================================

ABRAXAS NO es:

3. Notion con otro diseño.

5. Un calendario social.

18. Un sistema donde un asset no sabe a qué pieza pertenece.
19. Un sistema donde un resultado de IA crea una copia nueva de una pieza existente.
20. Una plataforma que oculta qué falta para terminar una publicación.

4. EL PROBLEMA REAL QUE ABRAXAS RESUELVE
================================================================================

Crear contenido no es el problema principal.

La generación se ha vuelto relativamente barata.

Los problemas reales son:

A. INCONSISTENCIA
La misma solicitud puede producir resultados muy diferentes.

B. PÉRDIDA DE CRITERIO
Una agencia sabe cómo debe hacerse algo, pero ese conocimiento no está estructurado.

C. ONBOARDING
Cada nueva persona tiene que aprender desde cero cómo piensa el cliente.

D. CONTEXTO REPETITIVO
Cada generación necesita volver a explicar marca, tono, audiencia, formato, etc.

E. DEGRADACIÓN EN LOTES
Mientras más piezas se generan, más probable es que:
- se repitan;
- sean genéricas;
- pierdan tono;
- no respeten formatos;
- inventen ejemplos;
- canibalicen ideas.

F. FALTA DE TRAZABILIDAD
No siempre sabemos:
- de dónde salió la pieza;
- qué prompt la creó;
- qué versión estaba aprobada;
- qué fuente sustentaba un claim.

G. PRODUCCIÓN FRAGMENTADA
Guion, visual, grabación, copy, portada y publicación terminan en herramientas distintas.

H. FALTA DE NEXT ACTION
El usuario sabe que "hay trabajo pendiente", pero no qué debe hacer ahora.

ABRAXAS busca resolver estos problemas estructurando el proceso completo.

7. PRODUCTION GRAPH
================================================================================

Production Graph es el modelo relacional interno.

No significa que el usuario tenga que ver un mapa de nodos.

Ejemplo interno:

    CONTENT joc-007
        ├── Script Task
        ├── Recording Task
        ├── Cover Task
        ├── IG Copy Task
        ├── LinkedIn Copy Task
        ├── Visual QA
        └── Publication

Dependencies:

    Recording
        depends on
    Script approved

    Final edit
        depends on
    Recording + B-roll

    Publication
        depends on
    QA + copy + final asset

El usuario no debe ver esto como una matriz técnica.

Debe ver:

    "Este Reel está al 74%.
     Falta:
     - grabación
     - portada
     - LinkedIn copy"

La complejidad pertenece al sistema.

18. JOC PHILOSOPHICAL CAROUSEL
================================================================================

Ejemplo de por qué Format Library importa.

Un JOC Philosophical Carousel no puede convertirse en:

    "7 lecciones de Séneca para emprendedores"

solo porque habla de filosofía.

Debe conservar el criterio previamente definido para el formato.

Entre las reglas ya definidas:

- JOC abre afirmando o negando una idea.
- Introduce claramente al filósofo relevante.
- La cita elegida debe corresponder realmente con el tema.
- El filósofo debe cumplir una función narrativa.
- El contenido debe aterrizar en una interpretación útil.
- El carrusel debe mantener identidad visual JOC.
- El copy debe parecer nativo de JOC.
- El cierre no puede ser una frase vacía.
- La filosofía no se utiliza como adorno.

He debe conocer esto automáticamente cuando format_id = joc_philosophical.

34. PODCAST INTRO ENGINE
================================================================================

A specialized cinematic content engine.

Target:

~80 sec.

Purpose:

make the audience need to watch the episode.

Not:

a trailer consisting of random powerful quotes.

Narrative architecture:

ACT 1
Podcast footage.

ACT 2
Voice-over + world building + B-roll.

ACT 3
Return to podcast + unresolved tension.
