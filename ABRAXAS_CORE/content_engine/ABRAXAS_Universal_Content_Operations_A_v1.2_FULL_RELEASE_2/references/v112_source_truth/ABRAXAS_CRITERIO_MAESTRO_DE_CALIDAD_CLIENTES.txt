ABRAXAS v1.1.1
CRITERIO MAESTRO DE CALIDAD, CONTENIDO, PROMPTS Y CLIENT INTELLIGENCE
SOURCE OF TRUTH PARA CONTENIDOS, TEXTOS, COPIES, IMÁGENES, VIDEO, PROMPTS, QA Y CONTEXTO DE CLIENTES

Documento complementario a:
ABRAXAS v1.1.1 · DEFINICIÓN MAESTRA DE PRODUCTO Y OPERACIÓN

OBJETIVO DEL DOCUMENTO

Este archivo define qué significa “calidad ABRAXAS” y cómo debe cambiar ese criterio según el cliente, el formato, la campaña y la pieza concreta.

No es un manual de estilo superficial.
No es una lista de adjetivos como “premium, moderno, humano, cinematográfico”.
No es una colección de prompts sueltos.

Es un sistema de decisión.

Debe permitir que una IA, un estratega, un copywriter, un diseñador, un editor o una persona que continúe el desarrollo de ABRAXAS pueda responder con precisión:

- ¿Qué hace que una pieza merezca publicarse?
- ¿Qué hace que una pieza sea genérica aunque esté bien escrita?
- ¿Qué debe cambiar cuando el cliente cambia?
- ¿Qué cosas pertenecen al criterio universal ABRAXAS y cuáles pertenecen al cliente?
- ¿Qué reglas debe respetar un formato específico?
- ¿Qué significa una imagen “correcta” para cada marca?
- ¿Qué diferencia un copy funcional de uno redundante?
- ¿Qué debe contener un prompt para ser realmente reutilizable?
- ¿Qué debe bloquear QA?
- ¿Qué puede inferirse y qué no?
- ¿Qué debe conservarse al producir contenido en lote?

===============================================================================
1. TESIS CENTRAL DE CALIDAD ABRAXAS
===============================================================================

ABRAXAS no busca producir contenido que simplemente sea correcto.

Busca producir contenido que combine:

    VERDAD
    + IDEA
    + ESTRUCTURA
    + IDENTIDAD
    + ESPECIFICIDAD
    + UTILIDAD
    + PRODUCCIÓN
    + TRAZABILIDAD

La calidad no se define por longitud, ornamentación o sofisticación aparente.

Una pieza ABRAXAS puede ser simple, pero no puede ser accidental.

Cada decisión debe responder a una función:

- ¿por qué existe esta pieza?
- ¿qué idea defiende?
- ¿para quién?
- ¿qué formato usa?
- ¿por qué ese formato?
- ¿qué hace cada beat/slide?
- ¿qué aporta el copy?
- ¿qué aporta la imagen?
- ¿qué evidencia necesita?
- ¿qué debe pasar después?

La frase que resume el estándar es:

    ABRAXAS considera de calidad una pieza cuando la idea es defendible, la estructura cumple una función, la identidad es reconocible, el contenido aporta algo específico, el visual ayuda a entender o sentir la idea, el copy complementa, las fuentes son seguras, la producción es ejecutable y el resultado no podría confundirse con contenido genérico generado por IA.

===============================================================================
2. LA JERARQUÍA DE CRITERIO
===============================================================================

Toda decisión debe pasar por cinco niveles.

NIVEL 1 — ABRAXAS UNIVERSAL
Reglas que deben cumplirse para cualquier cliente.

NIVEL 2 — CLIENTE
Brand Core, voz, audiencia, visual, claims, límites y contexto.

NIVEL 3 — FORMATO
Reglas específicas del formato seleccionado.

NIVEL 4 — CAMPAÑA
Objetivo, mensaje, CTA, timing y prioridad de una campaña concreta.

NIVEL 5 — PIEZA FIJADA
Decisiones humanas ya aprobadas para un content_id.

Precedencia normal:

    PIEZA FIJADA
        > CAMPAÑA
        > FORMATO
        > CLIENTE
        > UNIVERSAL

Pero una decisión inferior nunca puede violar una restricción de seguridad superior.

Ejemplo:

Una campaña puede pedir “más agresividad comercial”.

Eso no permite inventar resultados o claims que Brand Intelligence marca como no verificados.

===============================================================================
3. QUÉ SÍ ES CALIDAD ABRAXAS
===============================================================================

Una pieza ABRAXAS de calidad:

1. Tiene una razón concreta para existir.
2. Tiene una tesis, no únicamente un tema.
3. El hook crea una razón legítima para continuar.
4. El payoff cumple la promesa del hook.
5. Cada unidad añade información nueva.
6. Evita repetición semántica.
7. Explica mecanismos cuando el tema lo requiere.
8. Utiliza ejemplos concretos.
9. Distingue hecho, interpretación, hipótesis y aspiración.
10. Respeta el cliente.
11. Respeta el formato.
12. Respeta la plataforma.
13. Tiene un visual con función narrativa.
14. Tiene un copy con función propia.
15. Puede ser producido por otra persona sin adivinar qué quiso decir el estratega.
16. Conserva fuente y trazabilidad cuando corresponde.
17. Puede ser versionado y revisado.
18. Puede coexistir en un lote sin canibalizar otras piezas.
19. Tiene criterio suficiente para justificar por qué se publica.
20. Se siente creado para esa marca, no “adaptado” al final cambiando el logo.

===============================================================================
4. QUÉ NO ES CALIDAD ABRAXAS
===============================================================================

ABRAXAS no considera suficiente:

- gramática correcta;
- diseño bonito;
- frases inspiradoras;
- hooks exagerados;
- listas genéricas;
- “tips” intercambiables;
- conclusiones previsibles;
- grandes palabras sin mecanismo;
- imágenes decorativas;
- copy que repite la pieza;
- CTA automático;
- B-roll de stock sin relación;
- prompts llenos de adjetivos;
- usar “premium” como especificación;
- usar “cinematográfico” sin describir cámara, luz, ritmo y función;
- usar “hazlo como Apple” sin traducirlo a principios concretos;
- inventar experiencia personal;
- atribuir citas no verificadas;
- generar una serie donde cada visual parece de una marca diferente;
- producir seis piezas que son seis versiones de la misma tesis.

===============================================================================
5. AI SLOP: CRITERIO EXPLÍCITO ANTI-GENERICIDAD
===============================================================================

ABRAXAS debe combatir el AI slop de manera activa.

Se considera señal de slop:

- “En un mundo donde…”
- “¿Alguna vez te has preguntado…?” sin necesidad real.
- “No se trata de X, se trata de Y” usado mecánicamente.
- “El secreto que nadie te cuenta”.
- “Esto cambiará tu forma de…” sin demostrarlo.
- “Potencia / transforma / revoluciona” sin mecanismo.
- enumeraciones arbitrarias de 3, 5 o 7 puntos.
- tono de gurú.
- metáforas cliché.
- falsa tensión.
- CTA estándar tipo “guarda este post”.
- frase de cierre que repite el hook.
- uso excesivo de simetrías y contraposiciones.
- lenguaje que suena a IA aunque sea correcto.

El prompt debe contener anti-patrones reales del cliente y formato, no solo “evita clichés”.

===============================================================================
6. TEMA VS IDEA
===============================================================================

TEMA:
CRM.

No es suficiente.

IDEA:
Un CRM empieza a ser útil cuando otra persona puede retomar una oportunidad sin reconstruir la conversación desde cero.

La idea contiene una relación causal o interpretativa.

Otro ejemplo:

TEMA:
Validación de bioactivos.

IDEA MOKA:
Un resultado positivo aislado no permite decidir que existe una solución reproducible; la decisión necesita repetibilidad, diseño experimental y una cadena de evidencia.

Una pieza debe ser capaz de responder:

    ¿Qué afirmamos realmente?

===============================================================================
7. HOOK
===============================================================================

El hook no existe para “captar atención” de cualquier manera.

Crea un contrato narrativo.

Un buen hook produce una combinación de:
- relevancia;
- contradicción;
- reconocimiento;
- pérdida potencial;
- curiosidad;
- tensión;
- promesa específica.

MALO:
“¿Quieres mejorar tus ventas?”

GENÉRICO:
“El error que está destruyendo tus ventas.”

MÁS ABRAXAS:
“Tu CRM tiene 800 contactos. Dime cuál conversación toca mover hoy.”

El último ejemplo es específico, visualizable y abre un problema operativo real. Ese tipo de construcción aparece en el sistema editorial JOC ya desarrollado. 

===============================================================================
8. HOOK–PAYOFF CONTRACT
===============================================================================

Toda apertura crea una deuda.

Si se dice:

“Tu CRM no está fallando.”

la pieza debe explicar qué está ocurriendo en realidad.

Si se plantea:

“Una señal positiva no basta.”

la pieza debe demostrar por qué una señal aislada es insuficiente y qué decisión exige mayor evidencia.

FAIL automático si el hook crea una expectativa y el cierre se desplaza a otra conclusión.

===============================================================================
9. DESARROLLO
===============================================================================

Cada slide, beat, capítulo o bloque necesita una función.

Funciones útiles:

HOOK
CONTEXT
CONTRADICTION
DIAGNOSIS
MECHANISM
EVIDENCE
EXAMPLE
COMPARISON
CONSEQUENCE
DECISION
PAYOFF
CTA

Test de cada unidad:

    ¿Qué sabe o entiende la audiencia después de esta unidad que no sabía antes?

Si la respuesta es “lo mismo dicho diferente”, esa unidad probablemente debe eliminarse.

===============================================================================
10. PROFUNDIDAD
===============================================================================

Profundidad no equivale a más palabras.

Profundidad significa llegar al mecanismo.

SUPERFICIAL:
“Debes escuchar a tus clientes.”

MEJOR:
“Escuchar no cambia una operación si el equipo no distingue una objeción individual de un patrón repetido. El valor aparece cuando conversaciones dispersas se convierten en señales comparables.”

ABRAXAS busca explicar:

    qué ocurre;
    por qué ocurre;
    qué cambia la decisión.

===============================================================================
11. ESPECIFICIDAD
===============================================================================

Preferir:

“Un pipeline con 40 oportunidades sin next action”

sobre:

“Un pipeline desorganizado.”

Preferir:

“Una prueba salió bien y nueve repeticiones después no apareció el mismo resultado”

sobre:

“Un experimento puede fallar.”

La especificidad aumenta credibilidad y utilidad.

===============================================================================
12. UTILIDAD
===============================================================================

Una pieza debe producir al menos una consecuencia mental u operativa:

- entender algo;
- decidir algo;
- ver un problema de otra manera;
- adoptar un criterio;
- usar un framework;
- hacer una pregunta mejor;
- actuar;
- descartar una mala decisión.

Contenido que solo deja “bonita reflexión” es débil para ABRAXAS salvo que el objetivo explícito del formato sea puramente emocional/editorial.

===============================================================================
13. VOZ
===============================================================================

La voz no puede definirse solo con adjetivos.

“Directa, cercana, profesional” es insuficiente.

Debe expresarse en comportamientos.

Ejemplos de variables:

- afirma antes de explicar;
- pregunta antes de afirmar;
- utiliza primera persona o no;
- confronta ideas;
- nivel técnico;
- nivel de vulnerabilidad;
- humor;
- longitud de frase;
- vocabulario permitido;
- vocabulario prohibido;
- frecuencia de CTA;
- grado de seguridad de las afirmaciones.

Cada cliente necesita su propio Voice Behavior Profile.

===============================================================================
14. COPIES
===============================================================================

El copy no es una sinopsis automática.

Funciones posibles:

CONTEXTUALIZE
EXTEND
TRANSFER
CONVERT
DISCUSS
SOURCE
FRAME

Ejemplo malo:

Carrusel:
“Tu CRM no está fallando…”

Copy:
“Tu CRM no está fallando. Mira el carrusel para descubrir por qué.”

Ejemplo mejor:

“Cuando un equipo dice que ‘el CRM no funciona’, muchas veces el problema aparece antes del software: nadie ha definido qué debe ocurrir después de cada conversación comercial.

El CRM solo lo vuelve visible.

¿Qué parte de tu proceso sigue dependiendo de memoria?”

El copy añade contexto y abre otra capa.

===============================================================================
15. COPY POR PLATAFORMA
===============================================================================

No existe “el copy” como una sola pieza replicada.

INSTAGRAM
- puede ampliar contexto;
- conversación;
- acompañamiento visual;
- CTA social cuando tiene sentido.

LINKEDIN
- puede funcionar autónomamente;
- desarrolla tesis;
- experiencia;
- razonamiento profesional.

YOUTUBE
- framing;
- claridad temática;
- título/descripción;
- discovery cuando aplique.

TIKTOK
- puede ser más directo;
- menos contexto externo.

La plataforma cambia ejecución, no Brand Core.

===============================================================================
16. CARRUSELES
===============================================================================

Un carrusel no es un artículo dividido en pantallas.

Cada slide debe:
- cumplir una función;
- avanzar;
- conservar continuidad;
- poder comprenderse rápidamente;
- tener una jerarquía visual específica.

No todos los slides necesitan:
headline + párrafo + bullets + quote + badge + CTA.

Una idea dominante por lámina es una buena regla base.

===============================================================================
17. VIDEO VERTICAL
===============================================================================

El guion debe sobrevivir al oído.

No basta con que se lea bien.

Debe considerar:
- respiración;
- pausas;
- pronunciabilidad;
- ritmo;
- energía;
- mirada;
- cámara;
- edición.

MALO:
“En consecuencia, la implementación de herramientas…”

MEJOR:
“Muchas empresas instalan el CRM antes de tener un proceso comercial.

Ahí empieza el problema.

El software guarda información.
Pero nadie decidió qué pasa después de cada llamada.”

===============================================================================
18. HORIZONTAL
===============================================================================

No es un vertical largo.

Necesita:
- tesis;
- capítulos;
- progresión;
- resets de atención;
- ejemplos;
- payoff.

Cada bloque necesita justificar su duración.

===============================================================================
19. PODCAST CLIPS
===============================================================================

Todo clip debe funcionar fuera del episodio.

Necesita:
- contexto suficiente;
- speaker correcto;
- timestamps reales;
- tesis comprensible;
- consecuencia/payoff.

No inventar discurso.
No reescribir la voz del speaker como cita.
No seleccionar únicamente porque una frase “suena fuerte”.

===============================================================================
20. INTRO CINEMATOGRÁFICO DE PODCAST
===============================================================================

No es un montaje de frases intensas.

Debe construir necesidad narrativa.

ACT 1
Podcast footage que abre preguntas.

ACT 2
Voice-over que añade contexto, identidad y stakes + B-roll/archivo.

ACT 3
Regreso al podcast y tensión no resuelta.

La VO no repite el audio fuente.

===============================================================================
21. B-ROLL
===============================================================================

B-roll tiene función.

CONTEXT
EVIDENCE
METAPHOR
IDENTITY
PROCESS
LOCATION
SCALE
EMOTION
TRANSITION

MALO:
Persona escribiendo en laptop porque el tema es trabajo.

MEJOR:
Si se habla de oportunidades envejeciendo sin next action, visualizar registros que acumulan días sin siguiente paso.

===============================================================================
22. VFX
===============================================================================

VFX no demuestra destreza técnica.

Sirve para:
- aclarar;
- visualizar;
- enfatizar;
- conectar;
- transformar estado.

No usar:
“efecto futurista”.

Definir:
qué cambia;
cuándo;
por qué.

===============================================================================
23. SFX
===============================================================================

Un SFX debe declarar:

SOUND
WHEN
TRIGGER
LEVEL
FUNCTION

Si no hay evento que lo justifique:

    no_sfx_needed

===============================================================================
24. MÚSICA
===============================================================================

No:
“música inspiradora”.

Definir:
style
BPM
tonalidad/texture cuando ayude
energy
entry
build
ducking
resolution

===============================================================================
25. IMAGEN — PRINCIPIO GENERAL
===============================================================================

Una imagen no existe “para decorar”.

Debe cumplir al menos una función:

EXPLAIN
CONTRAST
ANCHOR
PROVE
ORIENT
HUMANIZE
SYMBOLIZE
CREATE TENSION
SHOW PROCESS
SHOW RESULT

La pregunta obligatoria:

    ¿Qué perderíamos si esta imagen desaparece?

Si nada cambia, la imagen probablemente es decorativa.

===============================================================================
26. PROMPT VISUAL
===============================================================================

No aceptar:

“Crea una imagen premium, moderna, cinematográfica, profesional.”

Un prompt visual necesita:

ROLE
PURPOSE
CANVAS/RATIO
SUBJECT
SCENE
COMPOSITION
CAMERA
LIGHT
MATERIAL/TEXTURE
PALETTE
BRAND ELEMENTS
TEXT ZONES
CONTINUITY
NEGATIVE CONSTRAINTS
OUTPUT

===============================================================================
27. CONTINUIDAD VISUAL
===============================================================================

Consistencia no es igualdad.

Una serie mantiene ADN:

FIJO
- paleta;
- comportamiento tipográfico;
- tratamiento fotográfico;
- textura;
- logo;
- motivos;
- densidad.

VARIABLE
- escena;
- sujeto;
- metáfora;
- composición dentro del sistema.

===============================================================================
28. PROMPTS — ESTÁNDAR ABRAXAS
===============================================================================

Un prompt ABRAXAS es una especificación de producción.

Debe contener:

ROLE
OBJECTIVE
CONTEXT
INPUTS
WHAT IT IS
WHAT IT IS NOT
STRUCTURE
CLIENT RULES
FORMAT RULES
EVIDENCE
RESTRICTIONS
NEGATIVES
OUTPUT CONTRACT
ACCEPTANCE CRITERIA
QA
HANDOFF
CONTINUITY

No todos los campos necesitan cientos de palabras.

Pero todos los conceptos necesarios deben existir.

===============================================================================
29. PROMPT: WHAT IT IS / WHAT IT IS NOT
===============================================================================

Esta dupla es fundamental.

Ejemplo JOC Philosophical:

ES:
Una interpretación práctica donde un filósofo y una referencia verificable ayudan a examinar una decisión actual.

NO ES:
- quote account;
- biografía;
- resumen académico;
- motivación genérica;
- “7 enseñanzas de…”.

Las definiciones negativas reducen ambigüedad.

===============================================================================
30. OUTPUT CONTRACT
===============================================================================

Si ABRAXAS espera estructura, la IA debe devolver estructura.

Ejemplo:

{
  "contentId":"...",
  "title":"...",
  "thesis":"...",
  "slides":[
    {
      "id":"slide-01",
      "function":"hook",
      "text":"...",
      "visualIntent":"..."
    }
  ],
  "copies":{},
  "qa":{}
}

No depender de parsing de texto libre cuando puede definirse un schema.

===============================================================================
31. CALIDAD EN LOTES
===============================================================================

Un lote no es bueno porque cada pieza aislada parece aceptable.

Debe evaluarse como conjunto.

Set-level QA:

DIVERSITY
COVERAGE
CANNIBALIZATION
FORMAT MIX
PILLAR MIX
CAMPAIGN ROLE
SEQUENCE
ENERGY

Test útil:

Si dos piezas pueden intercambiar sus hooks y seguir funcionando sin cambios, posiblemente son demasiado similares.

===============================================================================
32. SOURCE TRUTH
===============================================================================

Todo cliente debe tener fuentes clasificadas.

APPROVED PRIMARY
APPROVED SECONDARY
UNVERIFIED
CONTRADICTED
BLOCKED

Y cada afirmación puede tener estado:

FACT
INFERENCE
HYPOTHESIS
ASPIRATION
UNVERIFIED

ABRAXAS no transforma una hipótesis en hecho por repetición.

===============================================================================
33. CLAIMS
===============================================================================

No inventar precisión.

Los claims deben poder marcarse:

VERIFIED
APPROVED
DRAFT
UNVERIFIED
BLOCKED

Publicación debe bloquear claims críticos no aprobados.

===============================================================================
34. CITAS
===============================================================================

Una cita entre comillas implica atribución literal.

Si no puede verificarse:
- usar paráfrasis rotulada;
- o bloquear.

Especialmente crítico para:
- filosofía JOC;
- ciencia;
- testimonios;
- invitados de podcast.

===============================================================================
35. EJEMPLOS
===============================================================================

Ejemplos pueden ser:

REAL
HYPOTHETICAL
COMPOSITE

Nunca presentar un ejemplo hipotético como caso real.

===============================================================================
36. HUMAN-IN-THE-LOOP
===============================================================================

La IA produce candidatos.

No aprobación final.

Human reviewer decide:
- posición;
- gusto;
- claims de alto riesgo;
- formato final;
- publicación.

ABRAXAS automatiza lo repetible para reservar criterio humano a decisiones importantes.

===============================================================================
38. CRITICAL FAILS UNIVERSALES
===============================================================================

Bloquear si existe:

- cita fabricada;
- claim crítico no sustentado;
- speaker incorrecto;
- timestamp inexistente;
- formato específico roto;
- cliente equivocado;
- contenido aprobado sobrescrito;
- resultado IA tratado como aprobado automáticamente;
- visual muy fuera de identidad;
- schema imposible de hidratar;
- hook sin payoff;
- asset crítico incorrecto.

===============================================================================
40. JOC — CONTEXTO DE CALIDAD
===============================================================================

JOC combina marca personal, negocios, marketing, ventas, CRM, liderazgo, filosofía aplicada y podcast.

Su calidad no se logra “hablando de emprendimiento”.

La marca necesita postura, criterio, experiencia/observación y traducción operativa.

El contenido debe sentirse autoral.

No como contenido educativo genérico.

Dentro del sistema de agosto ya existen ejemplos donde la tesis, el formato, la fuente, la función del copy, la dirección visual y QA aparecen explícitos por pieza. Por ejemplo, el carrusel filosófico de Marco Aurelio se plantea como conversación entre filosofía y operación, con continuidad histórica, fuente/paráfrasis rotulada y copy que amplía la aplicación contemporánea; el carrusel CRM utiliza una escena concreta, cuatro campos operativos y una prueba de relevo. Esos son patrones de calidad, no solamente contenidos aislados.

===============================================================================
41. JOC — QUÉ SÍ ES
===============================================================================

JOC SÍ:

- tiene una posición;
- puede afirmar o negar directamente;
- aterriza conceptos a negocios/operación;
- puede utilizar filosofía como lente;
- explica con escenas reconocibles;
- usa ejemplos antes de elevarse a abstracción;
- puede ser confrontativo sin ser efectista;
- utiliza voz hablable;
- admite vulnerabilidad cuando es real;
- puede utilizar herramientas concretas;
- separa marca personal y voz de invitados.

===============================================================================
42. JOC — QUÉ NO ES
===============================================================================

JOC NO es:

- influencer motivacional;
- quote account;
- gurú de ventas;
- cuenta de “5 hacks”;
- divulgador académico de filosofía;
- CRM vendor genérico;
- presentador que convierte cualquier frase del invitado en tesis propia;
- marca de lujo basada en negro/dorado sin contenido de fondo;
- creador que usa hologramas de negocios como atajo visual.

===============================================================================
43. JOC — VOZ
===============================================================================

Comportamientos:

- abre rápido;
- reconoce situaciones reales;
- utiliza frases hablables;
- puede decir “esto no funciona” si puede explicar por qué;
- evita sentencia universal;
- muestra mecanismo;
- prefiere objeto/escena concreta a abstracción;
- no fuerza CTA;
- no fabrica experiencia.

El sistema editorial JOC existente especifica explícitamente evitar tono de manual, gurú o sentencia universal, y usar ejemplo antes de conclusión abstracta. 

===============================================================================
44. JOC — VISUAL
===============================================================================

Patrones ya fijados en contenidos aprobados/desarrollados:

- off-white / charcoal / rojo JOC controlado (#A91616 en el sistema actual);
- una idea dominante por lámina;
- espacio real para texto;
- continuidad de luz, sujeto, objeto y escena;
- cambio de encuadre cuando cambia la función narrativa;
- no recurrir a hologramas corporativos genéricos;
- rostro de JOC solo cuando el formato lo requiere;
- objeto conductor cuando puede explicar la tesis;
- visual que representa una capa del argumento.

En el formato filosófico pueden coexistir códigos históricos/editoriales con tensión actual, conservando continuidad visual entre slides. 

===============================================================================
45. JOC — CARRUSEL FILOSÓFICO
===============================================================================

Debe:

- comenzar con JOC afirmando o negando una idea;
- introducir al filósofo con relevancia real;
- usar cita verificada o paráfrasis claramente rotulada;
- hacer que el filósofo sea estructuralmente necesario;
- traducir filosofía a una decisión actual;
- evitar enseñanza académica;
- evitar motivación superficial;
- mantener una progresión clara;

108. MASTER PRINCIPLE: QUALITY IS OBSERVABLE
===============================================================================

ABRAXAS no debe decirle a una IA:

“hazlo bueno”.

Debe convertir “bueno” en condiciones observables.

Ejemplo:

Para este cliente,
para esta audiencia,
con este formato,
con esta idea,
con esta estructura,
con estas fuentes,
con este visual,
con estas restricciones,
el output debe tener estos campos
y pasar estos QA gates.

Eso es criterio operacionalizado.

===============================================================================

Si otra IA recibe este documento:

NO debe tratar Quality como Tone of Voice solamente.

NO debe hacer una plantilla universal y cambiar nombre/color por cliente.

NO debe crear prompts solo con adjetivos.

NO debe aceptar contenido gramaticalmente correcto como suficiente.

NO debe inventar estructuras cliente-específicas si no existen.

NO debe borrar anti-ejemplos.

NO debe sacrificar fuente/evidencia para simplificar contenido.

NO debe asumir que una imagen bonita cumple función.

NO debe asumir que un copy es resumen.

DEBE:

- cargar criterio universal;
- cargar Client Quality Pack;
- cargar Format Quality Pack;
- cargar Campaign Context;
- respetar decisiones fijadas;
- compilar prompts;
- devolver output estructurado;
- ejecutar QA;
- registrar errores por categoría;
- usar feedback para versionar formatos/prompts.

111. FRASE FINAL
===============================================================================

ABRAXAS no busca que la IA escriba como un humano genérico.

Busca que el sistema conserve suficiente criterio para que cada salida tenga una razón, una estructura, una identidad y un estándar verificable.

El objetivo final no es generar más.

Es lograr que una mayor cantidad de trabajo pueda producirse sin que calidad, contexto y conocimiento del cliente desaparezcan a medida que escala la operación.
