# ABRAXAS v1.1.3 Interface System 3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the ABRAXAS presentation layer from scratch while preserving the v1.1.2 domain, prompt, quality and automation contracts.

**Architecture:** `src/data.js` and `src/core.js` remain domain/knowledge inputs. A new `src/v113/` modular frontend owns presentation state, routing, components, projections, Brain Navigator, Architect, Studio and workspaces; root `src/app.js` becomes a minimal compatibility/bootstrap wrapper. LOCAL and WEB builds concatenate/load these modules in deterministic order.

**Tech Stack:** Vanilla HTML/CSS/JavaScript, Canvas 2D, localStorage, Python build/package scripts, Node browser-like smoke tests, Python unittest release gates.

## Global Constraints
- Preserve `content_id`, Campaign, Format, Task, Asset, Source Truth, History, QA, Production Graph and Automation contracts.
- No API secrets in standalone/web frontend.
- Dashboard and Product Story share the same data.
- Role projections are filters/views, never duplicate domain stores.
- One bootstrap only, at the end of the application bundle.
- LOCAL must run via `file://` with no CDN dependency.
- Product Story must not replace operational workspaces.
- Brain zoom exactly 1.0–2.0.
- `prefers-reduced-motion` support is mandatory.
- Every new module must expose empty/loading/success/error states where applicable.
