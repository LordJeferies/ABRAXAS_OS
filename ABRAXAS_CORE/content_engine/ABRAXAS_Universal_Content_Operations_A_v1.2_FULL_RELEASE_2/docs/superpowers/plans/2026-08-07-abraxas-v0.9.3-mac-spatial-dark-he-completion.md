# ABRAXAS A v0.9.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the standalone/offline ABRAXAS A v0.9.3 release with Mac Spatial Dark UX, dynamic client accent, completed He piece/batch workflows and visual/product regression gates while preserving the lightweight Production Graph.

**Architecture:** Keep `core.js` pure and testable, `data.js` as the seeded client/content/Branding Method dataset, `app.js` as state/render/interaction logic, `styles.css` as the Mac Spatial Dark interface system, and a deterministic build script that inlines all four into one standalone HTML. Batch planning remains a pure core function so independent L1/L2/L3 cadences can be tested without a browser.

**Tech Stack:** Vanilla HTML/CSS/JavaScript, Node.js logical tests, Python release tests/build/package, IndexedDB/File System Access when available with localStorage fallback.

## Global Constraints
- Offline-first; no external runtime dependency in the standalone HTML.
- Apple HIG/WWDC25 first for layout/material/motion; Google Material Motion only as fallback.
- Selective glass only on functional/focus layers; never glass-on-glass.
- Client accent identifies brand; semantic workflow states use independent colors.
- Physical output in He is sovereign; patterns are NATIVO/ADAPTADO, never blocked by source medium.
- He quantity 1–6 uses Coverage Map and avoids repeated angles.
- Batch mode supports 1 week / 2 weeks / 1 month and independent Low/Medium/High cadence for L1, L2, L3.
- L1 Low/Medium guarantees 1 Reel + 1 Carousel principal per week; L1 High guarantees 2 + 2.
- Stable contentId/taskId/asset path/graph relations must remain compatible.
- Prompt Quality Gate and strict prompt scan are mandatory before release.
