# ABRAXAS v1.2 Product Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the broken v1.1.3 presentation/action layer with a robust v1.2 interface while preserving the domain, prompts and automation contracts.

**Architecture:** Keep `src/core.js`, `src/data.js`, Quality Packs and automation data as domain inputs. Introduce `src/v120/` with a central store, domain projection engine, delegated action controller, Apple-grade shell/components, robust workspaces and Product Story. Root `src/app.js` becomes a minimal v1.2 bootstrap. Build LOCAL and WEB from the same modules.

**Tech Stack:** Vanilla JS modules packaged into standalone HTML, Canvas 2D, CSS, localStorage/IndexedDB-compatible browser state, Python build/package scripts, Node/browser-like tests, Chromium CLI where environment allows.

## Global Constraints
- Preserve all `content_id` values and existing domain objects.
- LOCAL must run under `file://` with no mandatory CDN or secrets.
- One bootstrap only.
- No inline `onclick` in v1.2 modules; use delegated `data-action` controller.
- Dashboard default; Product Story secondary.
- Liquid Glass restricted to functional/navigation layer.
- Base UI typography 15–17 px; no operational text below 11 px.
- `prefers-reduced-motion` and reduced transparency/contrast fallbacks.
- Automation uses confirmed-manifest only; source video read-only.
