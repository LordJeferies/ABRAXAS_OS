# ABRAXAS v1.1.3 · Interface System 3.0 Design

## Goal
Rebuild ABRAXAS presentation/interaction from scratch while migrating the v1.1.2 domain and knowledge intact. The release must feel like a coherent Apple-grade creative operations application, support solo and multi-role work, preserve Shim automation contracts, and expose the same Content through different role projections without duplicating data.

## Preserve exactly
- `content_id` and Content aggregate.
- Campaign, Format, Pillar, Task, Asset, Source Truth, History, QA, Calendar and Production Graph contracts.
- Client knowledge/Quality Packs for ABRAXAS, JOC, Moka Bio and INENERGY.
- Prompt compiler quality and v1.1.2 Shim/Automation schemas.
- `SHIM_CONFIRMED_MANIFEST`, `CUT_AUTOMATION_PACKAGE`, `CAROUSEL_PRODUCTION_PACKAGE`, Terminal and DaVinci executors.
- LOCAL standalone and WEB static build strategy.

## Replace completely
- app shell, navigation, renderers and legacy presentation state.
- main stylesheet/component system.
- Dashboard/Product Story renderers.
- Content Studio UI.
- Production UI and role-specific navigation.
- Brain implementation and Product Story motion layer.
- Architect UI/routing layer (keep knowledge/intent data, replace presentation and routing logic).

## Application architecture
The v1.1.3 frontend is split into explicit modules:

1. `domain-adapter.js`: reads v1.1.2 `ABRAXAS_DATA`/CORE and exposes stable selectors without mutating domain definitions.
2. `store.js`: presentation state only — section, presentationMode, roleMode, selected content/task, filters, inspector state, brain zoom.
3. `router.js`: deterministic section/role/piece navigation.
4. `components.js`: Apple-grade controls, sidebar, topbar, segmented controls, sheets, inspector rows, state views.
5. `dashboard.js`: role-aware operational Home.
6. `product-story.js`: Home/Clients/Brand/Roadmap storytelling projection using the same selectors.
7. `brain.js`: Brain Navigator 3.0 procedural canvas.
8. `production.js`: My Work + Writing/Recording/Design/Editing/QA/Publishing projections.
9. `studio.js`: Content Studio 2.0 with outline/workspace/inspector.
10. `architect.js`: contextual guide returning structured routes: target, reason, first action, success condition.
11. `shim.js`: v1.1.2 Shim wizard/exports ported into new workspace shell.
12. `library.js`, `assets.js`, `calendar.js`, `clients.js`, `branding.js`, `guide.js`, `roadmap.js`: focused projections.
13. `app.js`: one bootstrap at file end; composes modules only.

## Role model
`roleMode` is a presentation preference, not authorization. Values:
- `all`
- `strategy`
- `script`
- `copy`
- `recording`
- `design`
- `editing`
- `qa`
- `publishing`

The same Production Graph is projected differently. No role creates new Content/Task records.

### Script / Talent view
For video/reel content, show a clean list of spoken beats with only:
- functional label (`HOOK`, `DIAGNOSIS`, etc.)
- exact script text
- delivery note
- optional framing note
- target duration

Controls: `Modo lectura`, `Teleprompter`, `Mostrar indicaciones`. Teleprompter maximizes spoken text and removes production noise.

### Copy view
Shows pending platform copies, content summary, copy function, approved source text, manual editor, prompt, Copy/TXT/JSON/How to Use.

### Recording view
Shows scripts to record, duration, shot, location, delivery/energy, body/hands/gaze, checklist and source status.

### Design view
Shows carousel slide/cover/still tasks, approved text, function, visual direction, references/criterion, expected asset slot, with-text/without-text prompt, asset mapping and approval.

### Editing view
Shows timeline-like beats with source, B-roll, VFX/Omni, SFX, Music, Cover, Copies and START/MIDDLE/END references. This is the most complete audiovisual projection.

### QA / Publishing views
QA shows format-specific + universal gates and blockers. Publishing shows copy/asset/QA/date completeness and schedule/publish actions.

## Content Studio 2.0
An Apple professional-app anatomy:

`Outline | Workspace | Inspector`

- Outline: Overview, Content, Script, Recording, Visual, Editing, Copies, QA, Publish, History.
- Workspace: role-aware central object. Never render all data simultaneously.
- Inspector: metadata, campaign, lifecycle, production progress, source truth, expected assets, prompt composer and task status.
- Topbar: content type/format, role projection selector, previous/next content, exports, approval status.

## Dashboard / Product Story
Global top-right segmented control:
`Dashboard | Product Story`

- Dashboard: left sidebar visible; dense but calm operational workspace; role-aware.
- Product Story: sidebar collapses; top navigation remains; same data rendered as Apple product page: Hero → Get the Highlights → Take a Closer Look → How It Works → Built for How You Work → From Transcript to Timeline → One Content, Every Team.
- Switching modes never mutates domain data.

## Brain Navigator 3.0
The brain must be visually recognizable without explanation.
- Two hemispheres with central fissure.
- Organic outer contour with frontal/parietal/temporal/occipital hints.
- Procedural gyri/sulci guide curves.
- ABRAXAS chevron/point particles distributed inside the anatomical mask.
- Internal network links.
- Hotspots mapped to regions: He, Shim, Production, Assets, Calendar, Brand Intelligence.
- Each hotspot: always-visible symbol + leader line; hover/focus popover with purpose/CTA.
- Zoom 100–200%; 100% equals baseline, 200% reveals denser network/labels rather than only enlarging canvas.
- Product Story morph targets: brain → routes → content graph → production flow → calendar → published network.
- Reduced motion renders stable target and no continuous drift.

## Apple-grade design system
- System font stack; SF-symbol-like custom SVG icon family (no emoji/random icon sets).
- Dark graphite environment; stable content surfaces; client accent is semantic identity, not decoration.
- Liquid Glass only for sidebar/topbar/popover/sheet/Architect/segmented control/floating controls. No glass-on-glass content cards.
- Density sizes: compact 28–32px controls, standard 36px, primary 40–44px.
- Spacing scale: 4/8/12/16/20/24/32/48/64.
- Concentric radii and hairline separators.
- Motion ranges: 120–180ms feedback; 180–260ms selection/disclosure; 280–420ms sheet/source-anchored transitions; Product Story reveal 420–620ms. `prefers-reduced-motion` mandatory.
- Every workspace has empty/loading/success/error states.

## 41-technique registry
Do not apply all techniques as effects. Add `json/TECHNIQUE_REGISTRY_v1.1.3.json`; each module declares selected techniques, purpose, location, fallback, reduced-motion behavior and performance budget. Examples:
- Home Dashboard: state-reactive UI, next-action, data-driven layout, progressive disclosure.
- Product Story: sticky showcase, content reveal, context transition, scroll-driven narrative.
- Library/Assets: explorer, search/filter, persistent preview.
- Studio: synchronized selection, inspector, progressive disclosure, contextual toolbar.
- Shim: wizard, timeline coordination, state/reactive review, automation handoff.
- Production: task focus, dependency visibility, success/error feedback.

## Architect 3.0
A fixed-right utility window. It knows:
- current section
- presentation mode
- role mode
- selected `content_id`
- campaign/lifecycle/progress
- pending tasks/dependencies
- current selection/filter

Free-text intents map to route recommendations. Every recommendation includes:
- `target`
- `why`
- `firstAction`
- `expectedResult`
- `successCondition`
- direct navigation button

Example “¿Dónde puedo crear contenido?” returns:
1. He — from idea/brief/campaign.
2. Shim — from transcript/recording.
3. Library/Studio — extend/fix an existing Content.

## Shim / automation preservation
Port v1.1.2 contract unchanged in domain meaning. Shim result flow remains:
`Transcript → Master Prompt → review HTML → human confirmation → SHIM_CONFIRMED_MANIFEST → Terminal/FFmpeg + DaVinci`.
Only confirmed videos enter CUT automation. Confirmed carousels enter CAROUSEL production separately. Original source remains read-only.

## Error/recovery model
- Single bootstrap at end.
- State version `1.1.3` migrates presentation preferences from v1.1.2; domain data always loads from source-of-truth `data.js`.
- Import/AI hydration must preview mappings; no approved data overwritten silently.
- Empty/loading/success/error UI components standardized.
- Undo/history checkpoints remain meaningful, not every keystroke.
