# ABRAXAS A v0.9.3 · Mac Spatial Dark + He Completion · Design

## Release intent
v0.9.3 is the last strong P9 release before P10. It preserves ABRAXAS' lightweight Production Graph and local-first operation while replacing the accumulated web-dashboard feel with a calmer macOS-inspired information architecture. Apple HIG/WWDC25 defines visual hierarchy, navigation, material use, progressive disclosure and motion. Google Material Motion is only a fallback when Apple provides no equivalent behavioral guidance.

## Non-negotiable product model
ABRAXAS orders information into prebuilt prompts, sends those prompts to an external AI, maps the results back to the same content object, coordinates production/assets/QA/calendar and closes the lifecycle at PUBLISHED. A user can arrive without an idea and leave with one content piece, a multi-piece series or a full monthly grid.

## Interface system
Name: **ABRAXAS Interface System 1.0 · Mac Spatial Dark + Dynamic Client Accent**.

Four visual layers:
1. Environment: black/graphite canvas and restrained ambient gradients.
2. Content: opaque/semi-opaque solid surfaces for cards, editors, calendar, lists and documents.
3. Function: sidebar, toolbar, segmented controls, popovers, menus and command surfaces. Selective glass only here.
4. Focus: sheets, modal tasks, contextual inspectors and command palette.

Rules:
- No glass-on-glass.
- Content cards never use backdrop blur directly.
- Normal screens should expose no more than four simultaneous hierarchy levels: context, primary content, primary controls, contextual inspector.
- Client accent identifies brand, never workflow state.
- Errors/warnings/success/review/published keep semantic colors independent from client accent.
- All primary screens answer WHERE AM I / WHAT CAN I DO / WHERE NEXT without interaction.
- Motion communicates spatial relationship or state; it does not decorate.
- Honor `prefers-reduced-motion`.

## Client accents
ABRAXAS gold; Moka Bio Fresh Green/Sage/Deep Forest from its validated visual system; JOC uses its validated official accent when present in client data; INENERGY uses its validated brand accent. New clients receive accent tokens only from Brand Identity/Source Truth, never by invention.

Tokens: `--client-accent`, `--client-accent-strong`, `--client-accent-soft`, `--client-accent-glow`, `--client-accent-surface`, `--client-accent-border`, `--client-accent-text`.

## Shell and navigation
Sidebar groups: Operar (Dashboard, Clientes, Biblioteca, Calendario), Crear/Producir (He, Production Queue, Shim, Resultados IA), Sistema (Assets, Brand Intelligence, Guía, Roadmap). Sidebar is collapsible. Toolbar shows location, contextual subtitle and only frequent actions. Secondary commands move into `•••`/menus.

Saved operational routes remain visible but are reorganized into a two-row command shelf: Hoy, Esta semana, Por crear IA, Resultado IA, No revisado, Producción, Listo, Publicado, Sin fecha.

## Dashboard
Hero is reduced to roughly 280–330 px effective desktop height. Client selector updates the whole dashboard and accent. Metrics and pipeline occupy the next viewport region. Pipeline uses a horizontal readable track. Upcoming content cards show client, physical type, recipe, state and date. No word-break collisions.

## Client Intelligence
Selecting a client opens: Overview, Brand Core, Pilares, Formatos, Patrones, Copy Profiles, Branding Method, Sources. Summary badges such as “Sistema editorial”, “25 tools”, “2 copy profiles” are clickable and open contextual sheets explaining meaning, contents and impact on He/content creation. Client cards must never allow badges to overlap the brand name.

## Library and Content Studio
Library supports saved routes, client/type/pillar/status/lot filters and grid/list. Content Studio Overview immediately shows physical type, recipe/pattern, client, pillar, lot, lifecycle, date and production completion.

Content Studio 1×1 keeps editorial and visual production together. Prompt Composer exposes editable audience, problem, desired change, evidence, claims, CTA, primary platform, client pattern, universal pattern and structure. Editing these inputs recompiles prompts. Deep prompts are disclosure controls rather than permanently visible blocks.

## Calendar
Full month + backlog remain functional with drag/drop. A `Leyenda` button opens a detailed sheet explaining four dimensions:
- Client: accent color.
- Physical type: icon + text label.
- Production state: semantic dot/ring + text.
- Lot: L1/L2/L3 written explicitly.
No information depends on color alone.

## He — Content Factory
He has two modes in the same module: **Crear pieza** and **Crear lote**.

### Crear pieza
Flow: Client → physical output → pillar → client pattern → optional universal pattern → topic/context → quantity 1–6 → Coverage Map → editable structure → separate content prompt + visual prompt → save AI READY.

The physical output is sovereign. Client/universal patterns never block selection because their native format differs. Each pattern is marked NATIVO or ADAPTADO. Example: `Carrusel + Deep Explainer Moka` is valid; Deep Explainer's structural DNA is translated into carousel-native units. The pattern guides how the piece thinks, not what physical object is produced.

Client panel contains pillars, client patterns/series, copy profiles and contextual pattern information. Universal patterns remain a separate optional layer.

Micro-batch 1–6 must produce distinct angles via Coverage Map, not repeated paraphrases.

### Crear lote
Inputs:
- Client.
- Window: 1 week / 2 weeks / 1 month.
- Use existing content: yes/no.
- Pillars/platforms/pattern preferences.
- **Independent cadence for Lote 1, Lote 2 and Lote 3**. Each lot selects Low / Medium / High independently.

Cadence contract:
- L1 Low/Medium: minimum 1 principal Reel + 1 principal Carousel per week.
- L1 High: 2 principal Reels + 2 principal Carousels per week.
- L2 Low: 1 derivative/frequency piece per week; Medium: 2; High: 3.
- L3 Low: 1 support/story/simple piece per week; Medium: 2; High: 4.
- Window multiplies these weekly rules by 1, 2 or 4 weeks.
- Any combination is valid, e.g. L1 High + L2 Medium + L3 Low.
- If reuse is enabled, compatible unscheduled existing content fills slots before new AI READY pieces are proposed.

The lot preview shows per-week slots grouped by L1/L2/L3, with physical type, role, reused/new status and editable concept before saving.

## Production Queue
Default asks “¿Qué quieres resolver?” and groups Copies, Visuales, Video/B-roll, Portadas, QA, Publicación; then filters by client/type and finally opens one content/one task. `Ver todo` remains secondary.

## AI Results and Assets
Visual content-destination cards remain. Mapping always identifies target content, part/unit and type before hydration. Unresolved assets remain outside content until mapped.

## Guide
Outcome-first questions open expandable routes. Every route must explain: Dónde entrar → Qué seleccionar → Qué ocurre → Qué copiar → Dónde ejecutar → Qué vuelve → Dónde cargar → Cómo saber que terminó, plus an ABRAXAS example and `Ir al paso` actions.

## Roadmap
Replace growth capsules with a real tree/timeline visual. Nodes: Semilla → Raíces → Tronco → Ramas → Copa → Ecosistema. Selecting a node opens context: what was built, what capability it enabled, current status and what remains. Motion is subtle line-draw/opacity/scale, reduced under reduced-motion.

## Prompt and data quality
Preserve stable content IDs, task IDs, asset paths, relations and graph projection compatibility. All prompts remain autonomous and high-context. Prompt QA and strict scan remain release gates.

## Visual regression gate
Release blocks on: text overflow; button collision; stale version labels; calendar blank render; hidden physical type in content overview; glass-on-glass; unexplained color-only state; missing focus styles; missing reduced-motion; He pattern blocking; missing lot cadence controls; batch count mismatch; missing guide route detail.
