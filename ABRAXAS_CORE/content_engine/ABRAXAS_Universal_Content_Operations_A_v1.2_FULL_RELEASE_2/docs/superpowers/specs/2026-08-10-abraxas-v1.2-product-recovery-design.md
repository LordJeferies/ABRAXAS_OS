# ABRAXAS v1.2 · Product Recovery + Apple-grade Operations Design

## Goal
Recover ABRAXAS from the v1.1.3 presentation/interaction regression while preserving the stable domain and automation contracts. v1.2 must be visibly and operationally superior: buttons work through a central action system, production roles are coherent for solo/agency use, Calendar becomes an editorial planning tool, El Arquitecto becomes a real in-product guide, Shim retains its confirmed-selection automation contract, and Dashboard/Product Story reach a substantially higher Apple/macOS/CleanMyMac fidelity.

## Root causes found
1. v1.1.3 split the UI into many tiny modules, but several modules are only 5–20 lines and therefore lost task logic that existed in earlier releases.
2. The UI scale is far too small for the desktop viewport: many operational labels/cards use 7–10 px text, producing the large empty-black-space appearance seen in the screen recording.
3. Role mapping conflates Recording and Editing around the same `video` task type instead of deriving responsibility from source/asset/dependency state.
4. Calendar only renders dates + cards/backlog. It does not answer campaign balance, lot balance, risk, readiness, density, rescheduling reasons, or what must be solved before publication.
5. Inline `onclick` + globally exported handler names make the interaction layer brittle and hard to validate end-to-end.
6. El Arquitecto is still a response widget, not a route-aware guide that can inspect task/role/piece state and navigate to concrete controls.
7. Product Story has a generic particle shape, while the reference requires an unmistakable volumetric brain with persistent anatomy and semantic morphs.
8. Liquid Glass was treated as translucent dark panels instead of a distinct adaptive functional/navigation layer.

## Non-negotiable domain contracts
- Preserve all existing `content_id` values.
- Preserve Content, Campaign, Format, Asset, Source Truth, History, QA, prompts and Automation Bridge data.
- Role views are projections; never duplicate Content or Tasks.
- Shim only automates human-confirmed videos/carousels.
- `SHIM_CONFIRMED_MANIFEST.json` remains the source of truth for Terminal and DaVinci.
- Source video is READ ONLY.
- LOCAL remains usable via `file://`, without secrets or mandatory CDN.
- WEB remains a separate modular target.

## Interface architecture
### 1. Central action controller
Replace module-specific inline handlers with `data-action` attributes and one delegated controller. Every interactive control maps to a registered action with validation, state mutation, feedback and optional navigation. This makes the interaction graph testable.

### 2. Projection engine for work roles
Canonical modes:
- Solo / Yo hago todo
- Strategy / Editorial
- Script / Talent
- Copy
- Recording
- Design
- Editing
- QA
- Publishing

The same Content is projected differently. Recording and Editing are separated by dependencies/source readiness rather than by duplicated task records.

### 3. Workspace anatomy
Mac-style `Navigation Sidebar → Content/List → Detail/Inspector` where it improves a task. Every workspace has one dominant object/action, comfortable density, direct search/filter when justified, standard empty/loading/success/error states, keyboard focus and contextual inspector.

### 4. Dashboard
Primary operational view. It answers: what needs attention, what publishes today/this week, what is blocked, what belongs to me/my role, campaign health, and next action. A role changes the projection, not the data.

### 5. Product Story
Secondary representation of Home/Clients/Brand/Roadmap. Same data. Uses hero, Brain Navigator, Highlights rail, Closer Look selector, sticky showcases, chapter progress and product-story rhythm. No operational forms inside Story.

## Apple fidelity rules
- Liquid Glass only for sidebar/topbar/popovers/utility windows/segmented controls/transient controls.
- Content layer uses stable/standard material, never glass-on-glass.
- Sidebar floats over content; content can extend beneath it.
- Comfortable desktop density: base 15–17 px; secondary 12–14 px; no operational text below 11 px except rare metadata.
- One primary action per step/scene.
- Search on trailing toolbar for broad search; top of sidebar when filtering sidebar/list.
- Content hierarchy remains legible when transparency/motion is reduced.
- Every animation has reduced-motion fallback.

## CleanMyMac-derived operational rules
- One module protagonist and one primary task at a time.
- Fast direct entry to common tools/roles similar to My Tools.
- Process states explain what is happening.
- Results become reviewable tiles/rows, not an undifferentiated matrix.
- Background/derived work must not block reviewing already-available results.

## Calendar 2.0
Calendar is an editorial planning surface, not a date grid.
Modes: Month / Week / List / Backlog.
Each card shows client, physical type/format, campaign, lot, lifecycle and explicit risk.
Inspector shows scheduled date, dependencies, publication readiness, campaign/lot/pillar context and resolve actions.
Planning Insight computes format/pillar/lot density for current window and surfaces imbalances such as 4 reels / 0 carousels or excessive repetition.
Rescheduling supports drag/drop plus an accessible “Move” action and rollback.

## Role semantics
### Script/Talent
Read-only script first. Teleprompter mode. Unit list with only spoken text + delivery cue; no VFX/asset clutter.
### Copy
All missing or review-needed platform copies, with current content thesis, copy profile, prompt and How to Use.
### Recording
Video pieces whose spoken/source recording is missing or requires re-record. Shows shot, location, delivery, script checklist and source requirements.
### Design
Slides, covers, stills, graphics and asset slots with visual direction, source/reference criteria, with/without-text prompts.
### Editing
Only when recording/source exists or an external source is available; otherwise clearly blocked by Recording. Shows timeline beats, source, B-roll, VFX, SFX, music, cover and START/MIDDLE/END.
### QA
General + client + format-specific gates and Source Truth.
### Publishing
Only pieces close to publish, with explicit blockers, platform copies, final assets and schedule.
### Solo
Combined view organized by stage; not all metadata simultaneously.

## Architect 4.0
A local knowledge/route engine, fixed-right utility window. Context schema includes route/module, role, presentation, content_id, unit_id, selected task, campaign, lifecycle, progress, blockers, filters and next action.
A user question resolves to ranked routes with: answer, why, exact target, step sequence, expected result, return path and success condition. It can trigger a real navigation/highlight action. It never fabricates a function.

## Brain Navigator 4.0
Recognizable volumetric brain, not a generic oval:
- left/right hemisphere volume masks;
- deep central fissure;
- frontal/parietal/temporal/occipital density zones;
- cerebellar hint/brain stem silhouette;
- visible gyri/sulci line field;
- internal connection clusters;
- open-chevron ABRAXAS particles;
- 100–200% zoom with higher-detail layers at higher zoom;
- leader-line hotspots that remain readable;
- morph sequence brain→routes→content graph→production→calendar→published network.

## Shim/Automation preservation
Keep v1.1.2/1.1.3 contract:
Transcript → Master Prompt → review HTML → human state CANDIDATO/REVISADO/CONFIRMADO/NEEDS FIX/DESCARTADO → confirmed manifest → CUT package and carousel package.
Terminal/FFmpeg and DaVinci consume the same confirmed manifest.

## Technique Registry
Use the 41-technique library as a selection engine, not a checkbox. Each module declares technique IDs, observable task benefit, reference video, fallback, reduced motion, and performance budget. A technique fails the gate if disabling it improves clarity or if it has no observable task benefit.

## Success criteria

2. Dashboard, each role projection, Calendar, Studio and Architect have end-to-end state tests.
3. All v1.1.3 content IDs/domain values survive migration.
4. Recording and Editing are distinct projections with explicit dependency logic.
5. Calendar supports month/week/list/backlog plus planning insight and accessible reschedule.
6. Architect correctly answers at least 20 canonical intent queries and links to real targets.
7. Product Story Brain passes structural anatomy test and maintains 100–200% zoom.
8. No main operational typography below 11 px; base ≥15 px.
9. Liquid Glass selectors only match functional-layer components, not general content cards.
10. Shim/Automation contract and prompt QA remain green.
11. LOCAL standalone, WEB build and Client Intelligence build all boot.
12. FULL RELEASE contains source, tests, docs, visual/technique map, Automation Bridge, handoff, checksums and next-roadmap.
