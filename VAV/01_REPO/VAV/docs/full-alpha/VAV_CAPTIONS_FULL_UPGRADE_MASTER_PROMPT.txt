LOCAL REPOSITORY

~/Developer/VAV

PRODUCT
VAV Captions is the caption/subtitle module of the VAV family.

Primary pipeline:
ingest video
→ probe / normalize
→ transcribe
→ correct
→ segment / group
→ emphasize
→ style
→ structure
→ caption motion
→ scene/context-aware placement
→ preview
→ bake/render
→ export burned-caption MP4

VAV Captions is NOT a generic video editor. Keep these out of the captions core:
AI avatar, image generator, stock media, color-grading suite, general clip
cutting, video transitions, background removal, B-roll generator, music library,
noise-removal suite, recording studio, livestream.

FROZEN ARCHITECTURE
Desktop shell: Tauri 2, minimal Rust bridge.
UI: React, TypeScript, Vite, Tailwind v4, shadcn/ui where useful, Lucide,
Zustand, TanStack Virtual.
Editor: @remotion/player, wavesurfer.js, Moveable.
Contracts: Zod 4.
Central local runtime: VAV Node sidecar/local-engine, FFmpeg/ffprobe,
Remotion Renderer, Job Engine, Project Engine, Cache, CLI.
No Electron. No Next.js. No mandatory cloud.

REMOTION
Remotion is central:
CaptionPlan
→ CaptionComposition.tsx
→ @remotion/player for preview
→ @remotion/renderer for final advanced export.

FFmpeg remains responsible for probe, audio extraction, proxy, frame sampling,
scene detection, mux/codecs/VideoToolbox and optional ASS fast path.

MOTION CONTEXT POLICY
Motion manifests can come from TXT/MD/JSON or future Vav-motions output.
Each MotionContext can define:
- startUs / endUs
- motion family
- visual mode
- text ownership
- caption visibility
- Scene Smart mode
- placement hints
- safe-zone constraints

Example:
00:10-00:14 ABRAXAS_MOTION_03 center title

ABRAXAS_MOTION_03:
visual-motion owns center text;
standard captions may be suppressed;
Scene Smart is restricted.

GENERIC_BROLL:
caption engine keeps text ownership;
captions remain visible;
Scene Smart is required to find functional placement.

CONTENT PROJECTION
VAV Captions must accept TXT, MD, HTML or JSON with timestamp ranges such as:
00:02-00:07 hook: Strong opening
00:07-00:18 development: Explain the idea
00:18-00:24 close: Final statement

Roles can influence structure, emphasis, style scale, motion policy and Scene
Smart, but must never silently rewrite spoken transcript.

ALPHA → PRODUCTION HARDENING, IN PRIORITY ORDER

H1 — REMOTION RENDERER PARITY
Make preview and final export consume the exact same CaptionPlan/composition.
Replace Alpha FFmpeg/ASS as the primary advanced renderer with
@remotion/renderer. Keep ASS only as optional fast path.
Acceptance: preview/golden-frame parity, deterministic renders, progress,
cancel/retry, clean temp handling.

H2 — REAL WORD ALIGNMENT
Create AlignmentProvider separate from TranscriptionProvider.
Support timingQuality = word / segment / estimated.
Do not invent word timing or confidence.
Acceptance: progressive/highlight styles use true word timing where available.

H3 — SCENE SMART PRO
Add FFmpeg frame sampling, Sharp metrics, MediaPipe face/body detection,
face/eyes/mouth penalties, negative space, contrast/detail, platform safe zones,
continuity/hysteresis and motion/context priors.
Do not make captions chase faces frame-by-frame.
Acceptance: debug overlay with candidate scores/rejection reasons and stable
visual segments.

H4 — DOCKING / MULTI-WINDOW
Resizable panels, workspace presets, hide/show, detach/reattach Tauri windows,
shared synchronized state, saved geometry.
Never duplicate project mutation state per window.

H5 — AUTOSAVE / CRASH RECOVERY
Dirty state, debounced autosave, atomic writes, rolling checkpoints, recovery
UI, migrations, relink and backup retention.
Acceptance: kill app mid-edit and recover safely.

H6 — JOB ENGINE
Every long process gets id/type/status/progress/cancel/retry/logs/temp/error
classification. React must never freeze or force the user to guess if work is alive.

H7 — CACHE / INVALIDATION
Hash dependencies for probe, audio, transcript, scenes, frames, vision,
CaptionPlan and render intermediates.

H8 — PERFORMANCE
Virtualize long transcript/timeline data, memoize selectors, background workers,
waveform decimation and lazy thumbnails. Define measurable budgets.

H9 — PACKAGING
Ship VAV.app without requiring end users to manually install Node, FFmpeg,
whisper.cpp or developer tooling. Bundle/resolve runtimes safely and include
license/version registry. Never hardcode one user's paths.

H10 — PRODUCTION FILE SECURITY
Alpha development may use broad local asset scope.
Production must limit file access to user-authorized project/media roots.

H11 — AI BRIDGE
AI is optional. It may only produce validated VAV Actions.
Never execute arbitrary AI-generated code or mutate state without schema
validation and review.

H12 — VISUAL / INTERACTION QUALITY
Continue toward Apple-quality hierarchy and the user's CapCut/DaVinci/Riverside
references: interruptible springs, keyboard shortcuts, context menus,
accessibility, reduced-motion and high-density desktop editing.

H13 — GOLDEN QA
Unit + integration + Playwright where practical + golden-frame visual tests +
fixture media + corrupted-project fixtures + provider fallback + render parity.
