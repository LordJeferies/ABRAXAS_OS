0. PROPÓSITO DE ESTE TXT
======================================================================

Este documento concentra la lógica y las decisiones nuevas aprobadas desde
la última actualización de ABRAXAS OS para poder continuar el desarrollo en
otro chat sin perder contexto.

NO significa que todo lo aquí descrito esté implementado.
Debe distinguirse siempre entre:

- IMPLEMENTED / VERIFICADO
- IMPLEMENTED_UNVERIFIED_RUNTIME
- DESIGN_READY
- PLANNED
- REFERENCE
- LEGACY / HISTORICAL

Este TXT debe usarse como contexto de diseño y continuidad.
Antes de programar, el nuevo chat debe inspeccionar el repo real y comprobar
qué ya existe, qué es reutilizable y qué falta.

======================================================================
2. PRINCIPIO RECTOR DE ABRAXAS OS
======================================================================

ABRAXAS OS convierte criterio en infraestructura.

No es un chatbot.
No es un simple generador de prompts.
No es un Trello con IA.
No es un calendario social.
No es una IA que toma control creativo.
No es un sistema donde un render final destruye la editabilidad.

Es un sistema operativo de:
- inteligencia;
- creación;
- producción;
- organización;
- gerencia;
- publicación;
- medición;
- aprendizaje de contenidos.

Regla resumen:

YOD recuerda y piensa.
Shim observa y resuelve.
VAV produce.
He organiza, gerencia y muestra.
Arquitecto guía, acompaña y coach.
Lienzo conecta todo.
Publishing distribuye.
Metrics devuelve la realidad.
YOD aprende.

3. ROLES DEL SISTEMA
======================================================================

3.1 YOD
-------

YOD es el Core de Inteligencia de Contenidos.

Contiene o coordina:
- Client Core
- Brand Core
- Content Intelligence
- Format Library
- Structure Registry
- Pattern Library
- Prompt Intelligence
- Copy Intelligence
- Visual Intelligence
- Motion Intelligence
- Source Truth
- Opportunity Engine
- Coverage Engine
- Plan / Cadence Engine
- Content History
- Learning
- Metrics Intelligence

YOD puede crear:
- una pieza;
- varias;
- una semana;
- dos semanas;
- un mes;
- desde una idea;
- sin idea, usando Opportunity Engine;
- desde fuentes;
- desde grabaciones;
- desde gaps;
- desde campañas;
- desde aprendizaje previo.

YOD NO es un LLM.
Debe poder trabajar con lógica interna determinista.

3.2 LIENZO
----------

Lienzo es el objeto vivo, editable, versionado y trazable de cada contenido.

Nace temprano y evoluciona:

→ RECORDING

→ PRODUCTION

Secciones editables:
GENERAL

Regla:
GENERAR NO SIGNIFICA CERRAR.

Si un elemento cambia después de generar un artefacto:
- conservar artefacto previo;
- crear nueva versión;
- calcular impacto;
- marcar dependientes OUT_OF_SYNC o REVIEW;
- permitir revisar / regenerar / conservar;
- nunca sobreescribir silenciosamente.

3.3 HE
------

He es la ventana operativa y gerencial de ABRAXAS OS.

Debe servir tanto para una sola persona como para equipos.

NO son dos sistemas distintos.
SOLO y TEAM son dos vistas/proyecciones del mismo motor operativo.

HE permite:
- ver YOD;
- ver Client Core;
- ver oportunidades;
- ver planes;
- ver Lienzos;
- editar Lienzos;
- ver producción;
- manejar tareas;
- manejar equipo;
- asignar;
- revisar;
- administrar deadlines;
- ver dependencias;
- ver blockers;
- ver waiting-for;
- manejar calendario;
- organizar grabaciones;
- publicar;
- ver métricas;
- usar Arquitecto;
- time tracking;
- notificaciones internas;
- Kanban;
- dashboard gerencial.

3.4 SHIM
--------

Shim trabaja con material real.

Hace:
- source ingest;
- transcripción;
- segmentación;
- detección de speakers/scenes;
- structure matching;
- candidates;
- gaps;
- claims/evidence checks;
- editorial resolution;
- copy verification/update;
- recording gap feedback.

No inventa material faltante.
No convierte candidatos no confirmados en decisiones finales.

Loop deseado:
Shim detecta gap
→ YOD formula necesidad/pregunta
→ Arquitecto Recording Coach guía
→ nueva toma
→ Shim reanaliza

3.5 VAV
-------

VAV es el brazo de producción audiovisual.

Materializa:
- edición;
- captions;
- motions;
- visuales;
- renders;
- simple motion;
- artefactos audiovisuales.

VAV debe devolver al Lienzo:
- estado;
- versión;
- artefactos;
- timestamps;
- hashes;
- errors;
- provenance;
- eventos.

No debe crear otro source-of-truth paralelo.

3.6 ARQUITECTO
--------------

Arquitecto es una presencia transversal en todo ABRAXAS OS.

Es:
- asistente;
- guía;
- coach;
- productor;
- director;
- editor coach;
- copy coach;
- visual coach;
- motion coach;
- recording coach;
- VFX coach;
- SFX coach;
- music coach;
- QA coach;
- navegador;
- documentación viva;
- ayuda contextual;
- recomendador de provider de IA.

Arquitecto debe saber:
- dónde estás;
- de dónde vienes;
- hacia dónde vas;
- qué falta;
- qué está bloqueado;
- qué botón/ruta usar;
- qué hacer después;
- cómo saber que terminaste.

Arquitecto consulta:
- YOD para criterio;
- He para contexto operativo;
- Lienzo para estado;
- Shim para evidencia;
- VAV para producción;
- System Knowledge para saber cómo funciona ABRAXAS.

Arquitecto puede sugerir libremente.
Cambios relevantes al Lienzo requieren confirmación humana salvo
automatización autorizada expresamente.
