Mapa de archivos conocidos, función, autoridad, dependencias y próximos pasos
Fecha: 2026-08-28

======================================================================
0. PROPÓSITO
======================================================================

Este documento explica la razón de existir de las familias y archivos
actualmente conocidos del ecosistema ABRAXAS OS y propone un roadmap de
ejecución de mayor calidad.

No intenta fingir que conocemos cada archivo interno de todos los paquetes
históricos. Cuando un gran paquete tiene cientos o miles de archivos, se
explica su función como sistema y se indica que requiere auditoría file-level.

Objetivo:

PATH
→ QUÉ ES
→ POR QUÉ EXISTE
→ QUÉ AUTORIDAD TIENE
→ QUIÉN LO CONSUME
→ QUÉ NO DEBE HACER
→ QUÉ SIGUE

37. DEFINITION OF DONE POR FEATURE
======================================================================

Una feature no está DONE porque exista un archivo.

DONE exige:

spec aprobada;
schema/contract cuando aplique;
tests;
implementation;
integration;
error states;
permissions;
versioning;
docs;
status update;
Git commit;
remote SHA match.

Para features de UI:
también happy path + empty + loading + error + permission denied.

Para providers:
timeout + unavailable + malformed output + secret isolation.

Para imports:
hash + provenance + preview + rejection.
