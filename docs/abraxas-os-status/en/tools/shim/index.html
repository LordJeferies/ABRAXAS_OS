1. What It Is & Purpose

SHIM observes real material, compares it with what was planned and identifies what can be responsibly resolved. Its fundamental distinction is: PLANNED != OBSERVED != RESOLVED.

3. Problem Solved

Prevents silent misalignment between what was scripted and what was actually spoken or recorded on camera before downstream rendering begins.

4. Operational Example Flow

Raw take ingested -> Speech transcribed -> SHIM compares against planned 3-hook structure -> Identifies Hook 2 was spoken with 94% fidelity -> Emits timecode map to VAV.

5. Strict Ownership Boundaries

✓ What SHIM OWNS

  • Phonetic & semantic alignment verification
  • Planned vs Observed transcript discrepancy scoring
  • Gap detection matrix (missing hooks, omitted CTAs, improvised segments)
  • Resolution recommendation engine
  • OUT_OF_SYNC verification gate

✗ What SHIM DOES NOT OWN

  • Does NOT own raw audio transcription models (AI Runtime owns this)
  • Does NOT own original script writing (YOD owns this)
  • Does NOT own video segment cutting execution (VAV owns this)
  • Does NOT own task reassignment (HE owns this)

6. What It Is vs What It Is Not

What SHIM IS What SHIM IS NOT
A deterministic, domain-specific execution engine A generic third-party AI wrapper or chat prompt
Bound to immutable event and artifact schemas A mutable board with untracked edits
